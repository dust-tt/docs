---
title: "Skill Availability"
description: "Choose who can find and use a skill: its editors, every member, or members and agents."
---

Availability controls who can find a skill in the message bar and the Agent Builder, and whether agents can turn it on by themselves. You set it in the skill builder, in **Skill settings** > **Availability**. New skills start as **Editors only**.

## Availability options

| Availability | Who can find and use the skill | Permission needed |
| :--- | :--- | :--- |
| **Editors only** | Only the skill's editors. Use it while you build a skill, or for a skill you keep for yourself. | None |
| **Members** | Everyone in the workspace. Members add the skill in the message bar by typing `/` or clicking **+**, or add it to an agent in the Agent Builder. | **Manage skill availability** |
| **Members and agents** | Everyone in the workspace, plus any agent with [Discover Skills](/docs/user-documentation/agents/discover-skills), including **@dust**. | **Manage skill availability** and **Make skills discoverable to agents** |

A skill set to **Editors only** still works for other members when it's part of an agent or another skill they can use.

Once a skill is set to **Members and agents**, changing it back to **Members** or **Editors only** also requires **Make skills discoverable to agents**.

Admins and managers grant both permissions in **Admin** > **Governance** > **Agents & Skills**. By default, they're limited to admins. See [Roles, groups, and permissions](/docs/user-documentation/admins/admin-governance/workspace-governance-roles-groups-and-permissions).

## Before you choose Members and agents

With **Members and agents**, any agent with Discover Skills can turn the skill on by itself when a request matches it. The skill builder reminds you that the skill then has workspace-wide effects: many members can end up using it without choosing it.

Before you share a skill this way, check its **When to use this skill** text and its instructions. To see which skills agents can already use, open **Manage skills** and filter by **Members and agents**.

## Limit a skill to some members

Availability doesn't make a skill private. To limit who can use it, add a restricted Space or Pod in **Data and access**. Only people who are members of all the Spaces and Pods listed can use the skill, and that includes its editors.

## Change availability for several skills

In **Manage skills**, select several skills and use **Set availability**. See [Skills management](/docs/user-documentation/agents/skills/skills-management#update-several-skills).
