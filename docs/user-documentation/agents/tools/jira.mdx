## Overview

Jira tools let your agents manage Jira projects and issues from Dust. Agents can create and update tickets, track projects, and move issues through workflow transitions without leaving Dust.

## Key Features

| Tool | Description |
| --- | --- |
| `Issue Management` | Read, create, update, comment and move Jira issues |
| `Project Access` | Browse and manage accessible Jira projects |
| `Advanced Search` | Search issues with multiple filter criteria including custom fields or JQL syntax |
| `User Management` | Retrieve and work with Jira users |

## Available Tools

### Read

| Tool | Description |
| --- | --- |
| **Get Issue** | Read an issue by its key (for example PROJ-123). |
| **Get Issues** | Find issues by status, priority, labels, assignee, fix version, or dates. |
| **Get Issues Using JQL** | Search issues with a JQL query. |
| **Get Issue Read Fields** | List the fields that can be requested when reading an issue. |
| **Get Projects** / **Get Project** | List projects, or read one project by its key. |
| **Get Project Versions** | List the versions (releases) of a project. |
| **Get Issue Types** | List the issue types of a project. |
| **Get Issue Create Fields** | List the fields available for a project and issue type, before creating or updating an issue. |
| **Get Transitions** | List the status changes an issue can make. |
| **Get Issue Link Types** | List the link types that can be used between issues. |
| **Get Users** | Find users by email or display name. |
| **Get Attachments** | List the attachments of an issue. |
| **Read Attachment** | Read the text of an attachment (PDF, Word, Excel, CSV, plain text, with OCR for scans). |
| **Get Connection Info** | Get the connected user and Jira site. |

### Create and update

| Tool | Description |
| --- | --- |
| **Create Issue** | Create an issue in a project. |
| **Update Issue** | Change an issue's fields, such as summary, description, priority, or assignee. |
| **Transition Issue** | Move an issue to another status, such as In Progress or Done. |
| **Create Comment** | Comment on an issue. |
| **Create Issue Link** / **Delete Issue Link** | Link two issues (blocks, relates to, duplicates), or remove a link. |
| **Upload Attachment** | Attach a file from the Dust conversation to an issue. |

## Personal credentials vs Workspace credentials

|                                    | Description                                                                                                                                              | Benefits                                   |
| :--------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------- |
| Personal credentials (recommended) | Each user will use their own credentials to Jira. Agents using the Jira tool will only be able to perform actions that the current user can also perform | More secure                                |
| Workspace credentials              | The workspace admin logs in to Jira with a service account, all agents (no matter which user calls them) use that service account                        | No need for Jira credentials for each user |

You will then be redirected to an oAuth flow to connect an admin Jira. By default this tool is added to the Company data Space, so accessible in all the workspace.

## Usage in Dust

Once the tool has been configured by the admin as described before, it can be selected on any agent: in the Agent Builder, click on `Add Tool` and select Jira.

## Personal credentials usage

When users use an agent with the Jira tool for the first time, the agent asks them to connect their own Jira account.

Click on the `Connect` button to connect your own Jira credentials. And then, click on the `Retry` button to replay the agent answer.

From then on, requests will use the user's personal credentials, automatically inheriting their Jira permissions.
