title: "Auto models and the model picker"
description: "Choose a model for a conversation or an agent, or use an auto model and let Dust pick the model for you."
---

Every agent runs on a model. You can pick a specific model, or use an auto model: Dust then picks a model for you and keeps that choice up to date as new models come out. You choose the model of an agent in the Agent Builder, and you can change the model for your own messages in a conversation with the model picker.

## Auto models

An auto model is a tier that Dust maintains. When a better model comes out for a tier, Dust updates the tier, so your agents use it without any change on your side. There are three tiers:

| Auto model | What it's for |
|---|---|
| **Basic** | Quick, low-cost answers for simple tasks. |
| **Standard** | Most tasks. This is the best choice in most cases. |
| **Premium** | Complex tasks that need the most capable model. Answers are slower. |

The model picker shows the model that each auto model uses right now.

## Choose the model of an agent

<Steps>
  <Step title="Open the Agent Builder">
    Open the agent in the Agent Builder.
  </Step>
  <Step title="Open the model picker">
    In the **Instructions** section, click the button that shows the agent's current model.
  </Step>
  <Step title="Pick a model">
    Pick an auto model, or click **More models** to pick a specific model.
  </Step>
  <Step title="Save">
    Save the agent. Everyone who uses the agent now uses this model.
  </Step>
</Steps>

## Choose the model for your messages

You can use a different model for your messages in a conversation, without changing the agent:

<Steps>
  <Step title="Open the model picker">
    In the message input, click the model picker. You can also type `/` and select **Pick model**.
  </Step>
  <Step title="Pick a model">
    Pick an auto model, or click **More models** to pick a specific model. **More models** groups the models by the company that created them, like Anthropic, OpenAI, Google, or Mistral. The agent's model is marked **(Default)**.
  </Step>
</Steps>

Your pick stays selected for your next messages in the conversation, even if you mention a different agent. To go back to the agent's model, click **Revert to default** in the picker.

Your pick only applies in the Dust web app. When an agent runs from Slack or from a trigger, it uses the model of the agent.

## Reasoning effort

Some models can think for longer before they answer. When you select one of these models, the model picker shows a **Reasoning effort** slider under it. A higher effort can give better answers to complex questions, but the answer takes longer. A higher effort can also move the model into a higher [model access tier](/docs/user-documentation/admins/usage-seats-and-credits/model-access-tiers) and use more credits.

## Model access

Your workspace admins decide which models members can use. If a model or an auto model is locked in your picker, it's above your model access tier, or your plan doesn't include it. See [Model access tiers](/docs/user-documentation/admins/usage-seats-and-credits/model-access-tiers).

If an agent's model is above your model access tier, your message returns the **Model tier not enabled** error. You can pick a model that your tier allows in the model picker, or ask a workspace admin to raise your tier or to [let members run published agents above their tier](/docs/user-documentation/admins/usage-seats-and-credits/model-access-tiers#let-members-run-published-agents-above-their-tier).

If your workspace is in the EU region, admins can also limit the workspace to models hosted in the EU. See [EU-hosted models](/docs/user-documentation/admins/admin-governance/eu-hosted-models).

## When a model has issues

- **Provider issues:** when a model's provider has issues, the model picker shows an icon next to the model. An auto model skips that model and uses another available model of the same tier. A specific model stays selected.
- **The model declines to answer:** Dust answers with another model. The message shows **Answered by** and the name of the model that answered.
- **The model doesn't respond in time:** the error message offers to retry with another model tier, for example **Retry with Standard model tier**.

## Choose the model with the API

[Create a new conversation](/api-reference/conversations/create-a-new-conversation) and [Create a message](/api-reference/conversations/create-a-message) accept an optional `modelSelection` object. It changes the model for the agents mentioned in that message:

```json
{
  "modelSelection": {
    "providerId": "anthropic",
    "modelId": "claude-sonnet-5-5",
    "reasoningEffort": "medium"
  }
}
```

- `providerId` and `modelId` are required. `reasoningEffort` is optional.
- The change applies to that message only. It doesn't change the agent.
- If you don't send `modelSelection`, each agent uses its own model.
- The same access rules apply as in the app. If your workspace or your model access tier doesn't allow the model, the request returns a `400` error with the `model_disabled` code. An invalid object also returns a `400` error.
