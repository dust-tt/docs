title: Apps

An app is a Frame with a backend. In Dust, these are called **Frames with backends**.

By default, a Frame only shows what the agent put in it: anything a viewer types or changes is gone when the page reloads. An app remembers what people enter, so you can build task trackers, request forms, CRM views, and approval queues.

## What an app can do

A Frame with a backend can:

- **Run functions**: code that runs on Dust's servers when someone uses the Frame, for example to save a form entry or fetch fresh data.
- **Store data in databases**: records that everyone who uses the Frame shares. A Frame can have up to 4 databases of 1 GiB each.
- **Use your workspace tools**: functions can use the tools available in your workspace, such as Gmail, Slack, or HubSpot. Tool approvals and personal authentication work as they do in a conversation, and appear over the Frame.
- **Reach external services**: functions follow the same network access rules and secrets as [Computer](/docs/user-documentation/agents/tools/computer).

Functions also know who is using the Frame. The agent can use this for personal views, such as **My tasks**, or to reserve some actions to people who can edit the Frame.

## Create an app

Use an agent with the **Create Frames** skill (see [Add Frames to an agent](/docs/user-documentation/agents/frames/overview#add-frames-to-an-agent)), and ask for a Frame that saves data, for example: **Build a tracker for our launch tasks where the team can add, assign, and close items.** You can also ask the agent to add a backend to an existing Frame.

Data belongs to the Frame. When the agent improves the Frame later, existing data is kept. Exporting the Frame doesn't include its data.

To change an app without disrupting the people using it, work on a [draft](/docs/user-documentation/agents/frames/overview#work-on-a-draft) and validate it when it's ready.

## Who can create apps

Admins control Frames with backends in **Admin > Governance**, **Pods & Frames** tab, **Frames** section:

1. Turn on **Frames with backends** for the workspace.
2. Choose who can **Create Frames with backends**: **Everyone**, specific **Groups**, or **Admins only**. It's **Admins only** by default.

If you are not allowed to create Frames with backends, the agent tells you, and can offer a Frame without a backend instead.

## Share an app

Only signed-in members of your workspace can use a Frame's backend, with one exception for public links:

- **Workspace members**: you can share an app with anyone in your workspace. You can't invite people outside your workspace by email.
- **Anyone with the link**: the app needs at least one public function, which is a function the agent makes available to visitors. Visitors confirm their email with a one-time code before the app opens, and can only use its public functions.

Public functions can't use your workspace tools or secrets. They can still show data that the app's other functions saved in its databases. Tell the agent what visitors should be able to see and do, and it decides which functions to make public.

To add a backend to a Frame that you shared with people outside your workspace by email, first limit its sharing to workspace members.

For the general sharing options, see [Share a Frame](/docs/user-documentation/agents/frames/overview#share-a-frame).
