---
title: "Create your first agent"
description: "Create an agent, give it instructions, tools, and knowledge, test it, and share it with your workspace."
---

An agent is an AI assistant you set up for a specific job, like answering sales questions from your Notion pages or preparing meeting briefs. You give it instructions, then add the tools, skills, and knowledge it needs. This page walks through creating one in the Agent Builder.

You need the **Create agents** permission. By default, every member has it. If you don't see **Create agent**, ask an admin.

## Create the agent

<Steps>
  <Step title="Click Create agent">
    Click **Agents** in the left sidebar to open **Manage agents**, then click **Create agent**. You can also click **Create agent** at the bottom of the agent picker in the message bar. A conversation opens where an agent can build yours from a description. See [Conversational building](/docs/user-documentation/agents/conversational-building).
  </Step>
  <Step title="Choose how to start">
    To build the agent yourself, look under **Prefer to build manually?**:
    - **Open manual builder** opens an empty Agent Builder.
    - **Start from template** lets you pick a [template](/docs/user-documentation/agents/templates) for a common use case.
    - **Upload YAML** creates an agent from a file. See [Create an agent from a YAML file](#create-an-agent-from-a-yaml-file).
  </Step>
</Steps>

In the Agent Builder, [Sidekick](/docs/user-documentation/agents/default-agents/agent-builder-sidekick) helps you draft instructions and suggests tools and knowledge. The rest of this page follows the Agent Builder sections.

## Write the instructions

Instructions tell your agent what to do and how to behave. Describe its role, the steps it follows, and the format you expect. See [How to write effective instructions](/docs/user-documentation/agents/llm-best-practices/how-to-write-effective-instructions).

Sidekick can draft and improve your instructions. Its suggestions appear in the text, and you can accept or reject them one by one, or click **Accept all** or **Reject all**.

### Add suggested prompts

Suggested prompts show people what they can ask your agent. When someone selects your agent on the [homepage](/docs/user-documentation/getting-started/homepage), the prompts appear below the message bar, and a click sends one as their message.

In **Suggested prompts**, click **Add prompt** and write a question people could ask. You can add up to 4 prompts of up to 256 characters each.

## Add capabilities and knowledge

In **Capabilities and knowledge**:

- Click **Add capabilities** to give the agent [tools](/docs/user-documentation/agents/tools/index) and [skills](/docs/user-documentation/agents/skills/skills-overview), like web search or a CRM integration. The agent decides which ones to use for each request.
- Click **Add knowledge** to let the agent use your company data. In **Select data sources**, pick a Space, select the folders or pages the agent needs, like a Notion folder called "Sales Corner", and click **Next**. Then choose the **Knowledge lookup method**, like **Content search** for documents or **Analytics (tables, spreadsheets...)** for tables, and describe the data in **What's the data?**. The description helps the agent know when to use it.

Give the agent only the data it needs. The more data an agent can search, the harder it gets to find the right document.

**Data and access** lists the Spaces and Pods the agent uses data from. Only members of all of them can use the agent.

## Run the agent automatically

In **Triggers**, click **Add triggers** to run the agent on a schedule or when a webhook fires. See [Triggers](/docs/user-documentation/agents/triggers/index).

## Test your agent

Use the preview next to the builder to try your agent while you build it. Most agents need a few rounds of changes to their instructions or tools before they answer the way you want.

## Name, describe, and tag the agent

In **Settings**:

- **Name**: people call the agent by typing `@` and its name, so pick a short name that says what it does. You can also change its **Avatar**.
- **Description**: explain what the agent does and when to use it. It helps members pick the right agent, and helps **@dust** point people to it.
- **Tags**: tags group agents so members can find them. Click **Add** under **Tags**. Once the instructions are written, the list shows **Suggested tags** picked from the tags that already exist. Only admins can create new tags.

## Publish the agent and choose editors

In **Settings** > **Editors & access**, choose who can use the agent:

- **Published**: visible and usable by all members of the workspace. Members still need access to the data and tools the agent uses.
- **Unpublished**: visible and usable by editors only.

Publishing needs the **Publish agents** permission, which every member has by default. Click **Add editors** to let other people change the agent.

## Use your agent

- **In Dust**: type `@` followed by the agent's name at the start of your message.
- **In Slack**: type `@dust +agentname` before your message. Admins can also choose Slack channels where a published agent answers by default: in **Settings** > **Editors & access**, click **Slack preferences**.
- **In Zapier**: see [Using your agent in Zapier](/docs/user-documentation/agents/integrations/zapier).

## Create an agent from a YAML file

The easiest way to get a file in the right format is to start from an existing agent: open its details, then click **Export to YAML** in the **...** menu. Then click **Create agent**, choose **Upload YAML**, and pick your `.yaml` or `.yml` file. Dust creates the agent right away and opens it in the Agent Builder.

Before you import, check these fields:

- **Avatar**: `avatar_url` needs to be a Dust avatar (a URL starting with `https://dust.tt/static/`) or an image already uploaded to Dust. If it's missing or points somewhere else, the import fails. To use the default Dust avatar, set `avatar_url: "https://dust.tt/static/systemavatar/dust_avatar_full.png"`.
- **Editors**: editors are listed by email, and only members of your workspace are kept. When you import from Dust, you're added as an editor automatically. When you import with the API, at least one email needs to match a workspace member.
- **Tags**: every tag in the file needs to already exist in your workspace, otherwise the import fails.
- **Tools**: if a tool in the file can't be set up in your workspace, Dust skips it and tells you which ones were skipped. The agent is still created.

If the import fails, the error tells you why:

- **Invalid picture url**: `avatar_url` is missing or isn't a Dust avatar. See **Avatar** above.
- **Invalid YAML format**: the file doesn't match the expected structure. The rest of the message names the field at fault. Compare your file with an exported agent.

To import agents with the API, see [Import agent configuration](/api-reference/agents/import-agent-configuration). It also lists every field the file can contain.
