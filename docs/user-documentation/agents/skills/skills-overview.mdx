title: Overview
description: "Package instructions, knowledge, and tools into a skill once, then reuse it across your agents."
---

A skill is a reusable package of instructions, knowledge, and tools for a specific task, like logging a deal in your CRM or writing in your company's tone of voice. You write it once and add it to as many agents as you need. When you update a skill, every agent that uses it gets the change.

Dust provides [default skills](/docs/user-documentation/agents/skills/default-skills), like Discover Knowledge, Go Deep, and Create Frames. You can also create your own. For ideas, see [Skill examples](/docs/user-documentation/agents/skills/skill-examples).

## When to create a skill

Create a skill when:

- Several agents need the same instructions or tools.
- An agent's instructions are getting long, and part of them covers a task you could reuse elsewhere.
- You want one standard way of doing something across your team, like formatting a CRM entry.

To share instructions across agents, a skill is usually a better choice than a sub-agent. Use a sub-agent when a task needs its own separate context, like a long independent research run.

## Create a skill

You need the **Create skills** permission. Admins manage it in **Admin** > **Governance**. If you don't see **Create skill**, ask an admin.

<Steps>
  <Step title="Open Manage skills">
    Click **Skills** in the left sidebar, then click **Create skill**.
  </Step>
  <Step title="Choose how to build the skill">
    A conversation opens where an agent helps you write the skill. See [Conversational building](/docs/user-documentation/agents/conversational-building). To fill in the skill yourself, click **Open manual builder**. To import skills from a GitHub repository or a file, click **Start from existing**.
  </Step>
  <Step title="Fill in the skill builder">
    Complete the sections below, then save the skill.
  </Step>
</Steps>

## What goes into a skill

| Section | What to add |
| :--- | :--- |
| **When to use this skill** | When an agent should use the skill. Agents read this to decide whether the skill matches a request. |
| **Instructions** | The steps and guidelines to follow when the skill runs. |
| **Data and access** | The Spaces and Pods the skill can use data from. |
| **Files** | Files the skill can use when it runs, like templates, schemas, scripts, or reference material. |
| **Skill settings** | The skill's name and description, its editors, its [availability](/docs/user-documentation/agents/skill-availability), and [self-improvement](/docs/user-documentation/agents/self-improving-skills). |

### Add tools, knowledge, and other skills

Type `/` anywhere in **Instructions** to open a menu, then pick what to add. It appears as a chip in the text.

- **Tools**: the agent gets the tool while the skill is on. Say in the instructions when and how to use it.
- **Knowledge**: select **Attach** to search for a document by title, like a Notion page or a Google Drive file. You can also paste a page URL, and it turns into a knowledge chip. A URL that doesn't match a page stays a regular link. Agents that use the skill can search and read that knowledge.
- **Skills**: the agent can turn on the referenced skill when it needs it. Say in the instructions when to use it, for example: "Before writing the account brief, use the Sales validation skill to confirm the deal context."

Referencing skills lets you split a long skill into smaller ones and reuse each part in several skills. A summary of everything you referenced appears below the instructions.

## Use a skill

To add a skill to an agent, open the agent in the Agent Builder, click **Add capabilities** in **Capabilities and knowledge**, and select the skill. Members can also find skills from the message bar, depending on the skill's [availability](/docs/user-documentation/agents/skill-availability).

An agent turns on a skill only when the request needs it. Skills that don't apply stay off, which keeps the agent's context focused.

## Data and access

A skill can rely on data from specific Spaces or Pods, like a Notion page in the Product Space. In **Data and access**, list the Spaces and Pods the skill needs. Only members of all of them can use the skill, and an agent can only use the skill if it has access to all of them. Changes to this list apply right away to every agent that uses the skill.

**Editors** can change the skill's instructions, files, and settings. You choose the editors in **Skill settings**. Admins can open any skill in view-only mode, and click **Become an editor** to make changes.

## Track changes to a skill

Skills keep a version history. In the skill builder, click **History** at the top and choose a version to compare with the current one. To go back to that version, click **Restore all fields from this version**. Click **Leave comparison mode** to return to the current version.
