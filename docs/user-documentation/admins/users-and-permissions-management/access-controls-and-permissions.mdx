## **Core concepts definitions**

* **Workspace:** A Dust workspace is the main collaborative environment where teams can interact with AI agents, organize their data through spaces (open or restricted), manage connections to external tools, and control access through roles, governance capabilities, and groups.
* **[Connections](/docs/user-documentation/data-sources/connections):** Fully managed integrations that automatically sync data from external platforms (like Slack, Notion, Google Drive) to Dust, with granular control over what content is accessible. Connections are configured by Admins.
* **[Spaces](/docs/user-documentation/data-sources/overview):** Containers in Dust for organizing and controlling access to data. Open spaces are accessible to all workspace members; restricted spaces are limited to designated members. Spaces are managed by Admins.
* **Users:** Workspace members whose capabilities are determined by their assigned role (Admin, Manager, or Member), their seat type, their group memberships, and the governance capabilities those groups carry.
* **Admin:** A workspace user with full administrative authority who can manage all workspace settings including security (SSO, audit logs), billing, data connectors, spaces, groups, governance configuration, API keys, model providers, developer tools, and analytics. Admins always pass every governance capability check.
* **Manager:** An operational administrator with scoped access to the Admin area. Managers can manage members and manual groups, assign non-admin roles, view analytics, and edit seat types. They cannot access IT & Security settings, billing, API keys, model providers, or developer tools.
* **Groups:** Named sets of users that carry governance capabilities. Two types exist: manual groups (created in-product by an Admin or Manager) and SCIM-provisioned groups (synced from an IdP). Permissions are **additive**—a person gains the union of their role and all group-granted capabilities. A group exception grants additional access and never removes access granted elsewhere.
* **Governance capabilities:** Named permissions that control what groups of users are allowed to do. Each capability is set to **Everyone**, **Groups** (allowlist of groups), or **Admin only** mode. See [Admin governance](/docs/user-documentation/admins/users-and-permissions-management/admin-governance) for the full list.


## Access control policy

* Users can create agents based on the data of the spaces they have access to, provided they hold the `Create agents` capability.
* Users can interact with agents created with the data of spaces they are a member of.
* Publishing an agent requires the `Publish agents` capability; publishing a skill requires the `Publish skills` capability. These are separate capabilities.
* Editing an agent's or skill's content requires editor access to that resource; holding a publish capability does not grant editing rights.

## Workspace and space administration

**Who can perform each action:**

1. **Configure connections** — Admin only
   1. Authorize connections to company platforms and tools (Google Drive, Confluence, GitHub…)
   2. Select data scope at "folder" or document level
   3. Monitor data synchronization status
2. **Access policy definition** — Admin only
   1. Create dedicated spaces (open or restricted)
   2. Segregate company data between open and restricted spaces
   3. Define space membership
3. **Access policy management** — Admin only
   1. Add or remove space data based on user requests
   2. Manage space lifecycle (create, update, delete)
   3. Control members and access permissions
4. **Govern agents fleet**
   1. Create agents — requires `Create agents` capability (default: Everyone)
   2. Publish agents workspace-wide — requires `Publish agents` capability (default: Everyone)
   3. Deploy and distribute agents across groups — Admin or users with publish capability
   4. Monitor usage — Admin or Manager
5. **Governance settings** — Admin only (via **Admin > Workspace & Governance**)
   1. Configure governance capability modes (Everyone / Groups / Admin only)
   2. Manage groups and group memberships
   3. Toggle workspace features (Frames, Audit Logs)
   4. Manage billing and security settings

For the full governance model including all capabilities and their defaults, see [Admin governance](/docs/user-documentation/admins/users-and-permissions-management/admin-governance).
