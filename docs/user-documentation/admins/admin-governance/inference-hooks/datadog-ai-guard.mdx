<a id="before-you-start" />

Datadog AI Guard is in private beta. Ask your Dust team for access or email [inference-hooks@dust.com](mailto:inference-hooks@dust.com). You’ll need [AI Guard](https://docs.datadoghq.com/security/ai_guard/) enabled in your Datadog organization, an API key, and an application key with the `ai_guard_evaluate` scope.

## Connect Datadog AI Guard

Open **Admin > Security > Inference Hooks** and add a hook.

1. Choose **Datadog AI Guard**, select your **Datadog site**, and enter both keys. Select **Test connection** to check your credentials and AI Guard access. This test doesn’t send conversation content or evaluate your policies.
2. Start in **Monitor**. Choose your events, conversation history, and any groups to exclude. Sending more events or more history can increase your Datadog bill, even in Monitor mode.
3. If you want different Datadog tags, change **Service** and **Environment** under **Advanced settings**. The defaults are `dust` and `production`. Select **Create** to start checking live activity.

## Investigate in Datadog

To investigate a finding, open it in Dust and select **View in Datadog** if the link is available. A missing trace doesn’t mean the check failed. Dust can still show the finding.

## Update credentials

When you edit a hook, leave both key fields empty to keep your current keys. If you switch Datadog sites, enter new keys.

## Troubleshoot the connection

If **Test connection** fails, check that both keys belong to the selected site and the application key has the `ai_guard_evaluate` scope. For errors on live runs, see [Troubleshooting](/docs/user-documentation/admins/admin-governance/inference-hooks#troubleshooting).
