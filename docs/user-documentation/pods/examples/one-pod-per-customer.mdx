---
title: "One Pod per customer"
description: "Keep everything about a customer in one Pod, from first call to renewal, so sales and customer success work from the same context."
---

Sales and customer success teams can create one Pod per customer account. Notes, documents, and commitments stay in one place from the first call to the renewal, and agents prepare calls, track follow-ups, and summarize the account for anyone who needs it.

## Set up the Pod

| Setting | Recommendation |
| --- | --- |
| Name | One Pod per customer, named after the company, like "Acme Corp". |
| Access | **Restricted**. |
| Members | The account executive, the customer success manager, and the solutions engineer. |
| Files | The contract, discovery notes, and kickoff deck. Link the customer's documents and the product documentation from Company Data. |
| Instructions for agents | The relationship stage and current goal, like "Active pilot. Goal: 80% adoption by the end of the quarter." See [Give agents instructions for the Pod](/docs/user-documentation/pods/files#give-agents-instructions-for-the-pod). |

## Start simple

Use the Pod as the shared room for the account. Add a task for each next step, like "Send the pricing proposal" or "Schedule a security review," and assign it to its owner. Before a call, start a conversation and ask an agent for a prep brief: open tasks, recent discussions, and points to raise.

When the account moves from sales to customer success, the new owner joins the Pod and gets the full history.

## Automate account routines

- Create the Pod automatically: when a deal reaches a given stage in your CRM, a custom [webhook trigger](/docs/user-documentation/agents/triggers/webhooks/index) runs an agent that creates the Pod, adds the right people, and creates the first tasks, like "Complete discovery" and "Schedule kickoff."
- Add a weekly [schedule](/docs/user-documentation/agents/triggers/schedules) to an agent and pick the Pod under **Where to create this conversation?**. Each week, the agent posts an account summary: progress, risks, open tasks, and upcoming dates.
- After each customer call, a Fathom webhook trigger can run an agent that pulls action items from the transcript, creates tasks, and assigns them.

<Tip>
  Check the first run of a new trigger. The agent may ask for approval before it uses some tools, like creating tasks or adding members: click **Always allow** so later runs don't wait. For a trigger that serves the whole team, set **Credits** to **Workspace credits** so it doesn't use up one person's credits. See [Credits usage](/docs/user-documentation/agents/triggers/credits-usage).
</Tip>

## Go further

- Schedule an agent that searches the web for news about the customer, like funding, leadership changes, or product launches, and posts what matters in the Pod.
- Ask an agent to build an account health Frame, with usage data from your analytics tools, and pin it as the Pod banner. See [Frames](/docs/user-documentation/pods/frames).
- Ask questions about the account from anywhere: in any conversation, ask _"@dust, what's the status of the pilot in the Acme Corp Pod?"_ The agent finds the Pod and searches it, as long as you're a member. Naming the Pod helps it find the right one.

## What you get

Every account has a single source of truth, handoffs don't lose context, and nobody has to rebuild the history before a call.
