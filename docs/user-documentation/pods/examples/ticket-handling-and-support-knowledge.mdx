---
title: "Ticket handling and support knowledge"
description: "Turn incoming support tickets into Pod tasks, let agents draft answers, and build a shared memory of past resolutions."
---

Support and operations teams can run their ticket queue in one Pod. Each ticket becomes a task, agents draft answers from the team's documentation, and every resolved ticket adds to a shared memory that makes the next one faster.

## Set up the Pod

| Setting | Recommendation |
| --- | --- |
| Name | One Pod for the support team, like "Support". |
| Access | **Restricted**. |
| Members | The support team and its lead. |
| Files | Link the product documentation and the escalation playbook from Company Data. Keep a known issues document in the Pod, so agents can update it. |
| Instructions for agents | Tone of voice, escalation rules, and the topics agents must never answer alone. See [Give agents instructions for the Pod](/docs/user-documentation/pods/files#give-agents-instructions-for-the-pod). |

## Start simple

Create a task for each incoming ticket and assign it to a teammate. To get help with a ticket, click the play button (**Start working on task**): the agent searches the Pod's files and drafts an answer for you to review and send.

Resolved tickets stay in the Pod as conversations, so finding a precedent gets easier over time.

## Automate ticket intake

- Add a [webhook trigger](/docs/user-documentation/agents/triggers/webhooks/index) so an agent runs on each new ticket. Zendesk is a built-in source. For other tools, like Plain, Front, or Intercom, use a custom webhook. Pick the Pod under **Where to create this conversation?**, and ask the agent to create a task with the ticket's title, priority, and link.
- A teammate starts an agent on the task, reviews its draft, sends the answer, and marks the task done.
- At the end of each day, a [scheduled](/docs/user-documentation/agents/triggers/schedules) agent reviews the tickets resolved that day and flags recurring issues to the team lead.

<Tip>
  Check the first run of a new trigger. The agent may ask for approval before it uses some tools, like creating tasks or adding members: click **Always allow** so later runs don't wait. For a trigger that serves the whole team, set **Credits** to **Workspace credits** so it doesn't use up one person's credits. See [Credits usage](/docs/user-documentation/agents/triggers/credits-usage).
</Tip>

## Go further

- Let agents handle the first pass on each ticket: classify it, look for known solutions, and draft an answer. With the [Zendesk](/docs/user-documentation/agents/tools/zendesk) tool, the agent can save its draft on the ticket as a private comment for your team to review. Posting a public reply to the customer always asks a person to approve it first.
- Schedule a weekly agent that reads resolved conversations and updates the known issues document in the Pod.
- Schedule a monthly agent that writes a trends report, with the top topics, resolution times, and product areas that cause the most friction, to share with the product team.
- Point new hires to the Pod: they get every resolved ticket and every piece of documentation from day one.

## What you get

No ticket gets lost. Agents take care of triage and first drafts, people review and send, and what the team learns stays in the Pod for the next ticket.
