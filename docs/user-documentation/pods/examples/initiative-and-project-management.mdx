---
title: "Initiative and project management"
description: "Run a cross-functional initiative, like a launch or a hiring sprint, in one Pod with shared documents, tasks, and automatic progress updates."
---

Cross-functional teams can run a strategic initiative, like a product launch, a hiring sprint, or an OKR cycle, in one Pod. Documents, decisions, and tasks live in the same place, and agents keep everyone up to date on progress.

## Set up the Pod

| Setting | Recommendation |
| --- | --- |
| Name | One Pod per initiative, like "Q3 product launch". |
| Access | **Restricted** or **Open**, depending on how sensitive the initiative is. |
| Members | The owner of each workstream and the contributors. |
| Files | The brief, roadmap, and specs. Link related pages from Company Data, and add the roadmap as a [Pod tab](/docs/user-documentation/pods/files#show-files-as-pod-tabs). |
| Instructions for agents | The goal, success criteria, and key dates. See [Give agents instructions for the Pod](/docs/user-documentation/pods/files#give-agents-instructions-for-the-pod). |

## Start simple

Put every document about the initiative in the **Files** tab. Create a task for each deliverable and assign it to its owner. Use conversations to discuss, make decisions, and track open questions.

Anyone who joins the Pod gets the full history right away, so nobody has to ask for the latest version of a document or what was decided in last week's meeting.

## Automate progress updates

- Add a weekly [schedule](/docs/user-documentation/agents/triggers/schedules) to an agent and pick the Pod under **Where to create this conversation?**. Each week, the agent reads the Pod's activity and posts a progress summary: what shipped, what's in progress, what's blocked, and what's next.
- Ask the agent to also post the summary in the initiative's Slack channel, so stakeholders who aren't in the Pod stay informed. The agent needs the Slack tool.
- Pin a status Frame as the Pod banner, and ask the agent to update it with each summary. See [Frames](/docs/user-documentation/pods/frames).

## Go further

- Add a [webhook trigger](/docs/user-documentation/agents/triggers/webhooks/index) from GitHub, Jira, or Linear so an agent creates a task in the Pod for each new issue, keeping the Pod in sync with your project tool.
- Schedule an agent to read open tasks and recent conversations before each recurring meeting, and post an agenda.
- After each meeting, a Fathom webhook trigger can run an agent that pulls decisions and action items from the transcript, creates tasks, and assigns them to the right owners.
- When the initiative ends, ask an agent to read the full Pod history and write a retrospective.

## What you get

Everyone sees the same picture of what's done, what's in progress, and what's blocked. The Pod becomes the record of the initiative, from kickoff to retrospective.
