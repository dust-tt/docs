---
title: "Overview"
description: "Pods are shared workspaces where people and agents work together on conversations, tasks, and files around a common goal."
---

A Pod is a shared workspace in Dust where a team of people and agents works toward a common goal. Each Pod brings together, in one place:

- **Conversations:** discussions with agents and teammates. All Pod members can see them, and agents can use them as context.
- **Tasks:** work items that people and agents can create, assign, start an agent on, and complete.
- **Files:** the Pod's shared knowledge: uploaded files and folders, data from Company Data, and files that agents create, like [Frames](/docs/user-documentation/pods/frames).

In a Pod, agents can do what people do. They can start conversations, create and complete tasks, and save files, with or without a person in the loop.

## The Pods skill

Agents work with Pods through the Pods skill. All agents have it by default, including `@dust`, agents used in a Pod, and agents run by triggers. With the Pods skill, agents can:

- Find Pods by name.
- Start conversations in a Pod and post to them.
- Create tasks, work on them, and complete them.
- Upload and read files in the Pod.
- Search the Pod's knowledge and add data from Company Data.
- Create Pods and manage their members and settings, if they act for an Editor.

This makes Pods a good place for automations. For example, an agent run by a trigger can post a daily brief in a Pod, or open a conversation when a ticket comes in. For the full list of tools, see [Agent tools](/docs/user-documentation/pods/agent-tools).

## Open and Restricted Pods

| Visibility | Who can access it |
|---|---|
| **Open** | Anyone in the workspace can find the Pod and join it. |
| **Restricted** | Only invited members can access the Pod. An Editor must invite you. |

Workspace admins can allow only Restricted Pods. See [Admin controls](/docs/user-documentation/pods/admin-controls).

## Members and Editors

Each person in a Pod is a Member or an Editor. Members take part in conversations, tasks, and files. Editors can also manage members, visibility, and settings. See [Members and roles](/docs/user-documentation/pods/members-and-roles).
