---
title: "Websites"
description: "Crawl a public website so agents can use its pages, and choose how deep Dust crawls and how often it refreshes."
---

A website data source crawls the pages of a public website and keeps them in a Space, so agents can search their content. Use it for content you don't have in a connected tool, like your public help center, product docs, or a partner's documentation. PDFs hosted under the URL you crawl are included too.

## Before you start

- **The website must be public.** If a login is required to see a page, Dust can't access it.
- **Dust crawls from its servers, not from your browser.** Some websites block these requests. See [Websites behind bot protection](#websites-behind-bot-protection).

## Add a website

<Steps>
  <Step title="Open the Space">
    Open the Space where the website should be available, and click **Add data** > **Scrape a website**.
  </Step>
  <Step title="Enter the URL and crawl settings">
    Enter the website URL, then set how Dust crawls it:
    - **Crawling strategy**: **Only child pages of the provided URL** (default), or **Follow all the links within the domain**.
    - **Depth of search**: how many links away from the starting page Dust goes, from 0 to 5. The default is 2.
    - **Page limit**: the maximum number of pages to crawl, up to 1,024. The default is 50.
    - **Refresh schedule**: **Never**, **Every week**, or **Every month** (default).
  </Step>
  <Step title="Save">
    Give the website a name and save. Dust starts crawling, and the pages show up in the Space once the crawl is done.
  </Step>
</Steps>

To use the website in an agent, add it as [knowledge](/docs/user-documentation/agents/knowledge) in the Agent Builder. The @dust agent doesn't search websites on its own. To remove a website, open its settings and click **Delete this website**.

## Page size limit

Each page can hold up to 500,000 characters of text, measured after Dust converts the page to text. Pages above that size are skipped, and the sync still shows as successful, so the content of those pages won't be available to your agents.

If you need the content of a page that's too large, split it into smaller pages on your website, or upload its content as a file to a folder in a Space.

## A page is missing

If an agent can't find content from a page you expected to be indexed, check the page size first: pages over the size limit are skipped without an error. Then check that the page is public, isn't on a blocked website, and is covered by your **Page limit** and **Depth of search** settings.

## Custom headers

Under **Advanced settings**, you can add custom request headers. Dust sends them with every request the crawler makes to the website. After you save the connection, Dust hides header values. To change a value, remove the header and add it again.

## Websites behind bot protection

Dust doesn't fetch web pages from your browser. Requests come from servers in data centers, so bot protection services such as Cloudflare, Akamai or DataDome can block them or return a challenge page instead of the content. This affects website connections and agents that browse the web. Dust doesn't try to get around these protections.

If you control the website, you can let the Dust crawler through with a secret header:

1. Choose a header name and a long, random value that only you know, for example `X-Dust-Crawler` with a generated secret.
2. In your bot protection settings, add a rule that lets requests with that header and value through. In Cloudflare, use a WAF custom rule that matches the header and uses the **Skip** action. If Super Bot Fight Mode is on, make sure the rule skips it too.
3. Create a website connection for the pages your agents need and add the header under **Advanced settings**.
4. Add the connection to your agents' knowledge. Agents then read the synced pages instead of browsing them live.

The header is only sent by the website connection. Agents that browse the web with **Web Search & Browse** don't send it. Dust has no supported workaround for websites you don't control.
